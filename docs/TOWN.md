# 信号镇（town/）

信号镇是 Jojo 和 25 位伙伴上班的 3D 小镇。小镇里每个人都有一份岗位、一张工位和一个产出货架。你能看到谁在做什么、做到多少、做出了什么，像收菜一样把产出收进来。有人需要你拍板或者卡住了，也会在这里冒出来。

它是一个**独立的网页应用**，和公开展示站（`src/site`）分开构建、分开部署：

- 展示站承诺“不连接任何真实的 agent、账号或任务”，信号镇则是为了显示你自己 agent 的工作而做的，所以不放进展示站。
- 信号镇的构建产物在 `town/dist`，不会进入展示站的 `dist/`，也不受 `scripts/check-public-dist.ts` 的约束。
- 页面带 `noindex`，不会被搜索引擎收录。

## 本地运行

```sh
pnpm install
pnpm dev:town       # 开发服务器
pnpm build:town     # 类型检查 + 构建到 town/dist
pnpm preview:town   # 本地预览构建结果
```

## 小镇里有什么

| 地方 | 内容 |
| --- | --- |
| 信号广场（中心） | 信号塔，调度总管 Jojo 的工位，长椅和咖啡车 |
| 创作街（北） | GEO 文章、竞品对比、社媒、分享 PPT、设计 |
| 研究院（东） | 资讯侦察、深度研究、精读分析、SEO 审核、增长顾问 |
| 工程坊（南） | 开发、代码审查、PR 看护、安全审查、测试、自动化脚本 |
| 运营中心（西） | 晨报、运维值班、邮件、文档、数据分析 |
| 住宅区 | 26 栋小房子，下班的伙伴回家睡觉（屋顶会冒 Zz） |
| 游乐岛 / 农场岛 / 港口岛 | 休息和自由活动的去处；港口岛的信号门和“待入住”空地留给以后来做客的朋友的 bot |

每张工位上有：岗位道具（笔记本、画架、望远镜……）、朝向广场的名牌、状态灯、头顶的进度环（中间是正在做的产出类型），以及旁边能放 3 件产出的货架。

## 怎么玩

- **收菜**：货架上的方块就是做好的产出。点方块收一件，点货架上方的珊瑚色徽章收这个人的全部，或者点底部的「一键收菜」。
- **拍板**：头顶冒「?」的伙伴在等你决定，冒「!」的卡住了。点 TA，或者打开收件箱回复。
- **货架满了就停工**：每个货架最多 3 件。满了 TA 会站在工位上等你来收。
- **换岗位**：名册或员工卡片里可以给任何人换岗。一个岗位只有一个人；换上新人后，原来的人变成候补。
- **不在的时候**：演示数据会在你关掉页面后继续结算。重新打开（或者标签页在后台放了 10 分钟以上再切回来）时会弹出“欢迎回来”，告诉你这段时间做了什么、有几个问题在等你。标签页的标题也会显示待收的件数和问题数。

镜头：拖动旋转，右键拖动平移，滚轮缩放；WASD / 方向键移动，Q / E 转向，+ / − 缩放；双击一位伙伴，镜头会跟着 TA。

画质默认是「自动」：电脑先用高画质，手机和平板先用中画质，帧率跟不上时会自动往下降。也可以在设置里固定。

## 演示数据

默认显示的是小镇自己模拟的工作（`town/src/work/demo.ts`）：

- 每个岗位有自己的任务模板、话题、产出摘要、可能问你的问题和可能遇到的错误（`town/src/work/roles.ts`）。
- 一个任务 6～20 分钟；做完放上货架，休息 1.5～4 分钟再接下一个。大约 12% 的任务会做到一半来问你，6% 会在最后卡住。
- 白班 8:00–23:00（本地时间）；调度、资讯侦察、开发、代码审查、PR 看护、安全审查、运维值班这几个岗位通宵在岗。
- 模拟按事件时间推进、用固定种子的随机数，所以“离开三小时后一次结算”和“盯着看三小时”得到的结果完全一样（`tests/town/demo.test.ts` 会检查这一点）。
- 进度、货架、分工和收获记录都只存在这个浏览器的 `localStorage` 里。设置里可以重置。

### 改默认分工

第一次打开时谁做什么，写在 `town/src/work/roster.ts`：左边是角色 id（见 [CHARACTERS.md](CHARACTERS.md)），右边是岗位 id（见 `roles.ts`），写 `null` 的是候补。在小镇里改过的分工只存在你的浏览器里，不会改这个文件。

### 加一个岗位

在 `roles.ts` 的 `ROLES` 里加一项（指定所在街区 `district` 和桌上道具 `station`），工位会自动排进那个街区的那一排。每个岗位都必须有工位，`layout.ts` 在启动时会检查。

## 接入你自己的 agent

在 **设置 → 数据来源** 里填一个 JSON 地址（可选再填一个访问令牌）。小镇每 30 秒读一次，用它代替演示数据。令牌会以 `Authorization: Bearer <token>` 发送，只保存在这个浏览器里。地址需要允许跨域访问（CORS）。

格式（所有字段都可以省略；没出现在 `employees` 里的伙伴显示为候补）：

```json
{
  "updatedAt": "2026-10-29T09:30:00+08:00",
  "employees": [
    {
      "id": "o13",
      "role": "geo",
      "status": "working",
      "emotion": "focus",
      "task": { "title": "GEO 文章：品牌顾问的 72 小时调研流程", "kind": "article", "progress": 0.6 }
    },
    {
      "id": "o08",
      "role": "builder",
      "status": "needs-input",
      "request": {
        "id": "req-142",
        "kind": "input",
        "title": "登录页要不要加第三方登录？",
        "detail": "在做 PR #142，需要你决定范围。",
        "url": "https://github.com/…/pull/142",
        "createdAt": "2026-10-29T09:12:00+08:00"
      }
    }
  ],
  "outputs": [
    {
      "id": "out-981",
      "employee": "o13",
      "kind": "article",
      "title": "GEO 文章：独立顾问的 AI 研究助理",
      "summary": "约 1800 字，含 3 个案例",
      "url": "https://…",
      "createdAt": "2026-10-29T09:20:00+08:00"
    }
  ]
}
```

- `id`：角色 id（`jojo`、`o13`、`h04`……）。
- `role`：`roles.ts` 里的岗位 id 会排到对应工位；也可以写你自己的岗位名，这时 TA 没有固定工位，在镇上自由活动，产出照样能收。
- `status`：`idle`、`working`、`needs-input`、`success`、`error`、`offline` 之一，和角色库的 6 个状态相同。
- `emotion`：16 个表情之一（可选；不填时按状态自动选）。
- `task.kind` 和 `outputs[].kind`：`article`、`post`、`deck`、`report`、`code`、`review`、`mail`、`design`、`data`、`brief`、`ops`、`doc` 之一，决定方块上的图案。
- `outputs`：做好、等你收的东西。收过的 id 记在浏览器里，之后不会再出现在货架上；你的服务端不需要知道哪些被收了。
- `request.url`：在收件箱里显示为“去处理”的链接。实时数据模式下小镇不会替你回答问题。

## 部署到 Vercel

信号镇作为一个单独的 Vercel 项目部署，和展示站互不影响：

1. 在 Vercel 新建项目，导入这个仓库。
2. **Root Directory** 设为 `town`。安装和构建命令已经写在 `town/vercel.json` 里（回到仓库根目录执行 `pnpm install` 和 `pnpm build:town`），输出目录是 `town/dist`。
3. 部署。这个站点只有静态文件，没有服务端，也不保存任何数据。

如果接入了自己的 feed，建议给这个项目开启 Vercel 的访问保护（Deployment Protection），并把 feed 放在需要令牌的地址后面。

| `town/src/ui/` | 界面：顶栏、一键收菜、员工卡片、名册、收件箱、收获记录、设置、小地图、欢迎回来 |
